# Skill: Jeopardy Board Creator

## Purpose

This skill governs **all creation, validation, and persistence of Jeopardy game data** for the `jeopardy-screen` project. Every game is generated by AI. This skill is the single authoritative protocol for doing so correctly and compellingly.

> **Prior game history lives here:** See `.agents/skills/jeopardy-board-creator/prior-games/INDEX.md` for a full breakdown of every game that has been created. Read it before generating anything new.

---

## Invocation Protocol

When this skill is invoked to create a new game, execute these steps **in order**:

### Step 1 — Archive the Current Game

1. Read `data/games/current.json`.
2. Determine the next game number by counting existing archived files in `data/games/` (e.g., `game-002-YYYY-MM-DD.json`).
3. Read `data/manifest.json` to get the current game's `id`, `date`, and metadata.
4. Create a prior-game summary file at:
   `.agents/skills/jeopardy-board-creator/prior-games/<current-game-id>.md`
   using the **Prior Game Summary Template** (see below).
5. Append the current game as a new row to `.agents/skills/jeopardy-board-creator/prior-games/INDEX.md`.

### Step 2 — Plan the New Game

1. Ask the user (or accept from context) the **occasion / theme** and any **target topics or categories** for the new game.
2. Read `prior-games/INDEX.md` and relevant individual summary files to identify:
   - Categories already used (avoid verbatim repeats).
   - Specific clue topics already covered (avoid overlap).
   - Audience and occasion context for prior games.
3. Propose `columns` (number of categories) and `rows` (clues per category). Default is 6×5. Confirm with user if different.
4. Propose category names. Each must be fresh relative to prior games.

### Step 3 — Research & Verify All Facts

**Web search is mandatory. Research all topics in parallel.**

When categories or topics are known, fire off searches for all topics simultaneously — do not research one topic, write its clues, then move on. Batching research up front is faster and surfaces conflicts before you start writing.

For each topic search, gather:
- Key identifying facts, dates, names, and figures
- One or two memorable specifics at multiple difficulty levels
- Any disambiguation details needed if multiple answers are plausible

Accuracy standards:
- Verify every claim before including it. If a fact cannot be confirmed, cut it.
- No invented facts, quotes, statistics, or attributions.
- No "trick" clues that hinge on debatable or contested information.
- If multiple reasonable answers exist, add a single discriminating detail.
- Prefer primary sources (official records, original publications) over secondary sources.
- Dates, chart positions, award counts, biblical citations — confirm exact figures.

### Step 4 — Write All Clues

Follow the **Clue Writing Rules** (see below) for every question. Write all clues for all categories before proceeding.

### Step 5 — Validate

Run the validator:

```sh
npm run validate:data
```

The validator script is at `scripts/validate-board-data.mjs`. Fix **all** errors before continuing. Warnings should be reviewed; fix any that indicate a real problem.

To validate a specific (non-current) file:

```sh
node scripts/validate-board-data.mjs data/games/game-NNN-YYYY-MM-DD.json
```

### Step 6 — Save the New Game

1. Write the new game JSON to `data/games/game-NNN-YYYY-MM-DD.json` (next sequential number + today's date).
2. Overwrite `data/games/current.json` with identical content.
3. Add a new entry to `data/manifest.json` under `games[]` and update the `"current"` field to the new game's `id`.

### Step 7 — Create Prior Game Summary for the NEW Game

After the game is saved, create its own summary file at:
`.agents/skills/jeopardy-board-creator/prior-games/<new-game-id>.md`

This file will be used when the *next* game is created.

## Board Data JSON Schema

All game files must conform to this schema:

```json
{
  "id": "game-NNN-YYYY-MM-DD",
  "title": "Human-readable game title",
  "date": "YYYY-MM-DD",
  "description": "One-sentence description of the occasion and themes.",
  "columns": 6,
  "rows": 5,
  "pointValues": [100, 200, 300, 400, 500],
  "categories": [
    {
      "name": "CATEGORY NAME IN ALL CAPS",
      "questions": [
        {
          "points": 100,
          "question": "Clue text written in Jeopardy voice.",
          "answer": "What is the answer?",
          "revealed": false
        }
      ]
    }
  ],
  "metadata": {
    "createdBy": "AI",
    "occasion": "Occasion or event name",
    "targetAudience": "Description of target audience",
    "topics": ["topic1", "topic2", "..."]
  }
}
```

**Constraints enforced by the validator:**
- `categories.length` must equal `columns`
- Each category's `questions.length` must equal `rows`
- Each category must contain exactly one question at each point value in `pointValues`
- `revealed` must be `false` on all questions
- No duplicate clue text or answer text across the entire game

## Manifest Schema (`data/manifest.json`)

```json
{
  "current": "game-NNN-YYYY-MM-DD",
  "games": [
    {
      "id": "game-NNN-YYYY-MM-DD",
      "title": "Game Title",
      "date": "YYYY-MM-DD",
      "filePath": "data/games/game-NNN-YYYY-MM-DD.json",
      "columns": 6,
      "rows": 5,
      "pointValues": [100, 200, 300, 400, 500],
      "categoryNames": ["CAT 1", "CAT 2", "..."],
      "topics": ["topic1", "topic2", "..."],
      "metadata": {
        "occasion": "...",
        "targetAudience": "...",
        "createdBy": "AI"
      }
    }
  ]
}
```

## Clue Writing Rules

### Voice & Format
- Write in **Jeopardy voice**: the clue describes the answer; the contestant responds with "What is…?" or "Who is…?"
- Clues are declarative statements, not questions.
- Category names are ALL CAPS, concise (1–4 words), and thematically tight.

### Clue Length
- **Target 10–20 words** per clue; hard maximum 30 words.
- One sentence. One identifying fact.
- No stacked clauses, parenthetical asides, or compound lists.
- If trimming a clue loses accuracy, choose a simpler fact — don't stretch the word count.

### Traditional Jeopardy Format
- **Clue (`question` field):** A terse declarative statement — the descriptor Alex Trebek would read aloud. It provides context, definition, or a single characteristic that points to one answer.
- **Response (`answer` field):** The entity being identified — a single name, place, title, or short phrase. Prefix with `What is`, `Who is`, etc. Keep the response itself brief; it should name the thing, not describe it.
- Bad clue example: `"This long-running NBC sitcom, set in New York City and starring six friends including Ross, Rachel, Monica, Chandler, Joey, and Phoebe, first aired in 1994."`
- Good clue example: `"Six friends in New York City starred in this hit 1990s NBC sitcom."`
- Good answer: `"What is Friends?"`

### Answer Format
- All answers must begin with: `What is`, `Who is`, `What are`, `Who are`, `What was`, `Who was`, or equivalent Jeopardy-standard phrasing.
- End with a `?`.
- The answer names the thing — it does not repeat the clue's description.

### Do Not Give Away the Answer
- The clue must not contain the answer or a near-verbatim paraphrase of it.
- Run the mental test: "If I read just the clue, is the answer stated outright?" If yes, rewrite.

### Difficulty Ladder
- **100 pts** — Broad, well-known fact; accessible to most players.
- **200 pts** — Slightly more specific; requires recall of a key detail.
- **300 pts** — Requires knowledge of a supporting character, event, or secondary fact.
- **400 pts** — Specific detail that rewards deep knowledge; a stumper for casual players.
- **500 pts** — Niche, specialized, or obscure fact that only genuine enthusiasts will know.

### Audience
- Primary audience: **millennial adults born in the late 1980s**.
- Heavy preference for 1990s and 2000s pop culture, technology, sports, and news.
- Earlier references are acceptable if they were culturally prominent during the 90s–2000s.
- Avoid hyper-local or obscure regional references unless the occasion demands it.

### Avoiding Overlap with Prior Games
- Read `prior-games/INDEX.md` before planning categories.
- Do not reuse a category name from a prior game verbatim.
- Do not write a clue about a topic already covered in a prior game's `topics` list, unless the angle is substantially different and the clue could not be confused with the prior one.
- Specific named entities (people, songs, books, concepts) from prior games should not appear as the primary answer in new clues.

## Prior Game Summary Template

When archiving a game, create `.agents/skills/jeopardy-board-creator/prior-games/<game-id>.md` using this template:

```markdown
# Prior Game: <title>

**ID:** <id>
**Date:** <date>
**Occasion:** <occasion>
**Audience:** <targetAudience>
**Grid:** <columns> categories × <rows> questions | Points: <pointValues>

## Categories & Key Topics Covered

### <CATEGORY NAME>
- <100-pt topic / named entity>
- <200-pt topic / named entity>
- <300-pt topic / named entity>
- <400-pt topic / named entity>
- <500-pt topic / named entity>

[...repeat for each category...]

## Full Topic Index

[Comma-separated list of all topics/named entities that appeared as primary answers, for quick overlap scanning]
```

## Audio Generation

TTS (text-to-speech) audio is **not** generated as part of this skill's normal workflow. Do not run `generate-tts.mjs` or any audio generation commands unless the user explicitly requests it.

Audio is an optional, separate step handled outside the game creation process.

## Quick Checklist Before Saving Any Game

- [ ] Every fact in every clue was verified via web search
- [ ] No answer text appears verbatim in its own clue
- [ ] Each category has exactly `rows` questions, one at each point value
- [ ] Total category count equals `columns`
- [ ] `revealed: false` on every question
- [ ] No duplicate clue text or answer text across the game
- [ ] `npm run validate:data` passes with no ERRORs
- [ ] `data/games/current.json` updated
- [ ] `data/manifest.json` updated (new entry + `current` field)
- [ ] Prior game summary file created for this game
- [ ] `prior-games/INDEX.md` updated
